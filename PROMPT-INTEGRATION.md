# Промт для подключения раздела «Парсер» к example.com

Добавь в существующее меню `example.com` пункт «Парсер». Используй стили сайта и текущие правила доступа. И интерфейс, и серверные маршруты этого раздела доступны пользователям с разрешением работать с компаниями.

## Форма

- «Город» принимает название города и вариант «Все города России». В API для всех городов передавай `все`.
- «Компания или категория» принимает название или категорию и вариант «Все». В API для всех категорий передавай `все`.
- «Количество» принимает целое число от 1 до 100. Начальное значение 20.
- «Найти компании» запускает поиск. Проверь поля до отправки и заблокируй повторное нажатие до окончания поиска. Сохраняй фильтры при ошибке.

## Серверное подключение

Проксируй вызовы через backend `example.com`. Читай `PARSER_API_BASE_URL` и `PARSER_API_KEY` из серверных переменных. После настройки DNS адрес API будет `https://parser.example.com`. Для каждого защищённого вызова передавай `Authorization: Bearer <PARSER_API_KEY>`. Секрет хранится на сервере. Проверяй доступ пользователя, а для маршрутов со входом по cookie используй существующую защиту CSRF.

Отправляй `POST /v1/search` с `Content-Type: application/json`. Сервис по умолчанию ищет в 2ГИС и Яндексе.

```json
{"city":"Таганрог","company":"Стоматология","limit":20}
```

```json
{"city":"все","company":"все","limit":10}
```

Ответ `202` содержит `{"job_id":"<идентификатор>","status":"running"}`. Опрашивай `GET /v1/search/{job_id}` каждые 2 секунды, пока `status` равен `running`. Браузерный поиск может занять несколько минут. Показывай «Идёт поиск» и удаляй таймер опроса при уходе с раздела. Задай общий срок ожидания 5 минут. Останови опрос при `complete`, `partial` или `failed`. API хранит недавние задания в памяти, поэтому `404` после перезапуска означает необходимость заново запустить поиск.

Пример завершённого задания с неполной выдачей.

```json
{
  "job_id": "536f417686984c1cae660f0057281ac04",
  "status": "partial",
  "requested": 20,
  "returned": 1,
  "companies": [
    {
      "id": "2gis:org:123456789",
      "name": "Пример компании",
      "address": "Таганрог, Примерная улица, 1",
      "phones": ["+70000000001", "+70000000002"],
      "socials": ["https://vk.com/example", "https://t.me/example"]
    }
  ],
  "issues": []
}
```

Покажи «Найдено N из X», если строк меньше запрошенного количества. При пустой выдаче без `issues` покажи «Непрозвоненные компании не найдены». Сообщения `issues[].message` покажи как текст с названием источника. При `429` используй `Retry-After` и разреши пользователю повторить запрос. Для `422` покажи ошибку формы. Ответ `401` означает, что ключ на стороне сайта требует проверки. При недоступности API покажи ошибку и кнопку повторного запуска.

## Выдача и прозвон

Покажи таблицу со столбцами «Название компании», «Точный адрес», «Номера телефонов», «Соцсети», «Прозванивалась». На узком экране размести те же поля в карточке. Отображай телефоны и соцсети через `; ` и используй `—` для отсутствующих значений. Для соцсетей сделай кликабельными действительные HTTP- и HTTPS-ссылки. Отрисовывай текстовые значения как текст.

Галочка «Прозванивалась» вызывает `PUT /v1/companies/{company_id}/called` через backend сайта. Используй URL-кодированный `id` из карточки. Запрос без тела. В ответе `200` приходят `id`, `called: true`, `called_at`. Скрывай строку после успешного ответа. При ошибке оставь строку и разреши повторить отметку. Отметка сохраняется на VPS и исключает компанию из следующих результатов.

Проверь оба фильтра из примеров, разделитель нескольких контактов, неполную и пустую выдачу, ошибку запроса и сохранение отметки. После отметки проведи повторный поиск с теми же фильтрами и проверь, что компания исчезла.
